## C1 — Patched-weight training eval fails the provenance gate
**Files:** `kernels/training/stories_train.m`

**Root cause:** `rebound_plan_for_weights` (`core/ane_runtime.m:102-106`) recomputes `sha256` from patched bytes and stores it in the returned program's `prog->plan`. `plan_has_same_provenance` (`ane_runtime.m:419`) includes `sha256` in the eval gate. But `patch_layer` (`stories_train.m:1150-1153`) deliberately preserves the *original* plans, so after `orion_trainer_recompile_delta` the trainer's `kern->plan_*.weights[i].sha256` (old) never matches `prog->plan.weights[i].sha256` (new) → every `orion_eval_with_plan` returns `ORION_EVAL_NOT_INVOKED`.

**Fix:** In `patch_layer`, after each successful `orion_program_patch_weights`, refresh the corresponding `kern->plan_*` from the patched program's plan. `OrionBindingPlan` is all fixed-size arrays (verified) so `*orion_program_plan(prog)` is a safe deep copy, and the pointer is owned by the program (valid for its lifetime — must copy before any release). Concretely, change the `PATCH_PROGRAM` macro so that after `replacement.field = orion_program_patch_weights(...)` succeeds, it does `*(kern->plan_field) = *orion_program_plan(replacement.field)` for each weighted program. The weight-free `sdpa_bwd2` (no patch, plan unchanged) needs no change. Since `patch_layer` rebuilds `replacement` from `*kern` and the comment at 1150-1152 claims plans "remain valid," this implements the comment's intent correctly.

**Verification:** add a compiler-only regression is hard here (requires ANE). Instead, add an assertion in `orion_train_step` after the first post-patch eval loop that `orion_eval_with_plan` returned true (so a regression fails loudly in the training log rather than silently producing zeros). Manual: run one training step + `orion_trainer_recompile_delta` and confirm eval results are non-zero and `orion_compile_count` is unchanged (patch path doesn't compile).

## C2 + C3 — KV-cache bounds checks are incomplete (silent corruption + heap overflow)
**Files:** `kernels/inference/kv_cache.h`, `kernels/inference/kv_cache.m`, `kernels/inference/decode_cpu.m`, `kernels/inference/decode_ane.m`

**Root cause:** `store_prefill`/`append` return `void` and early-return on overflow, but callers ignore the skip and proceed with inconsistent state: `prefill_kv` sets `current_len` past capacity (C2), and both `decode_step` (C3) and `decode_ane.m:orion_ane_decode_step` (same bug, third caller the kernels reviewer missed) compute `cache_len = pos+1 == max_seq+1`, overreading the cache by one row and (in `decode_step`) overflowing the fixed `ws->scores` buffer.

**Fix (make the mutators fail-closed end-to-end):**
1. **`kv_cache.h` / `kv_cache.m`:** change `orion_kv_cache_store_prefill` and `orion_kv_cache_append` to return `bool` (`false` on the existing bounds-violation paths, after the stderr print). Also add a defensive `layer < 0 || layer >= cache->n_layer` check to both (Minor M1) returning `false`.
2. **`decode_cpu.m` — `orion_gpt2_prefill_kv`:** make the function return `bool`. At top: `if (seq_len < 0 || seq_len > kv->max_seq) { fprintf(stderr, ...); return false; }`. Replace the unconditional `kv->current_len = seq_len;` (line 337) with: only set it after the per-layer loop succeeds. Actually cleaner — check the `store_prefill` return at line 311 and `return false` on failure before the layer loop completes (the store happens inside the layer loop, so bail mid-loop). The prefill logits were already computed for the last position, but on overflow we discard them and fail loudly.
3. **`decode_cpu.m` — `orion_gpt2_decode_step`:** at top (after `pos = kv->current_len`), guard `if (pos < 0 || pos >= kv->max_seq) { fprintf(stderr, "orion_gpt2_decode_step: KV cache full ..."); return; }` — leave logits untouched, do NOT increment `current_len`. (Keep `void` return to avoid churning 11 callers; the guard prevents the overflow. The function signature stays `void`.) This single guard fixes C3 because the `append`-skips-then-`cache_len=max_seq+1` path can't be reached when `pos >= max_seq` is rejected up front.
4. **`decode_ane.m` — `orion_ane_decode_step`:** add the identical guard at top (after `pos = kv->current_len`, line 144): `if (pos < 0 || pos >= kv->max_seq) { fprintf(stderr, ...); return false; }`. It already returns `bool`. This fixes the same overflow the reviewer missed.
5. **Update `decode_cpu.h`:** change `orion_gpt2_prefill_kv` signature to `bool` return. Update its callers (`infer.m`, `bench.m`, and the tests) to check the return — on `false`, print and abort generation. For the void `decode_step`, no signature change.

**Verification:** new test `tests/test_kv_cache_bounds.m` (compiler-only, no ANE/model blobs): create a KV cache with `max_seq=4`, call `prefill_kv` with `seq_len=5` → assert it returns `false` and `current_len` is still 0; fill the cache to capacity then call `decode_step` → assert it returns without writing logits and `current_len` stays at `max_seq`. Register in Makefile `COMPILER_TEST_BINS`. (The existing `test_decode.m`/`test_infer_golden.m` suites exercise the happy path under `max_seq` and will confirm no behavior change.)

## C4 — `test_plan_weight_dict.m` SKIP→PASS regression
**Files:** `tests/test_plan_weight_dict.m`

**Root cause:** file doesn't include `orion_test.h`, declares its own `g_passed`/`g_failed` (no skip counter), and 5 cases use `printf("SKIP(...) "); return true;` which counts as PASS and makes `main` exit 0.

**Fix (minimal, preserves the per-case structure):**
1. Add `#include "orion_test.h"` after the existing imports.
2. Add `static int g_skipped = 0;` next to the existing `g_passed`/`g_failed` (line 14).
3. Replace the 5 cases' `printf("SKIP(...) "); return true;` idiom with a helper macro/inline that prints `SKIP`, increments `g_skipped`, and returns a sentinel. Simplest: change each `return true;` in a skip context to `{ g_skipped++; printf("SKIP\n"); return false_for_counting_purposes; }` — but that conflates with FAIL. Cleaner: introduce `#define SKIP_CASE(reason) do { printf("SKIP(%s)\n", reason); g_skipped++; return; } while(0)` and change the 5 test functions from `static bool test_*` to `static void test_*` (no return value), updating the `TEST(name)` macro to just call and track pass/fail/skip via a per-case flag set inside the function. Concretely: convert each `test_*` to take no return and use a local `bool ok = true;` that assertions set to `false`; the macro reads a shared `g_last_case_ok`. Simplest robust approach: keep `static bool` functions but make the SKIP path set `g_skipped++` and `return true` is *removed* — instead the function sets a `g_last_case_skipped` flag and returns `true` (counted as not-failed), and the macro prints SKIP/FAIL/PASS based on the flag.
4. Final `main()` return: `if (g_failed) return ORION_TEST_FAIL; if (g_skipped && !g_failed) return ORION_TEST_SKIP; return ORION_TEST_PASS;` — implementing FAIL>SKIP>PASS precedence.
5. Use `ORION_TEST_SUMMARY(g_passed, g_failed, g_skipped)` before the return to emit the `RESULT:` line the runner parses.

**Verification:** `make build/tests/test_plan_weight_dict && ./build/tests/test_plan_weight_dict` on this (non-ANE-capable CI or by temporarily stubbing `orion_ane_init`) — confirm exit code 77 and `RESULT: SKIP ...` line. On an ANE host, confirm exit 0 and all 8 cases PASS.
