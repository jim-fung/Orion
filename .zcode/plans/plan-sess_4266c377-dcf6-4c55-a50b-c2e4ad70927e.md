# Migrate depth-serve seqpack to canonical plan-aware execution

## Scope and ordering

Implement the Orion side in four logical commits, with the shared BLOBFILE validation foundation first. Keep protocol v2, phase-timing diagnostics, compile budgets, seqpack recurrence semantics, and stdout receipts unchanged. Do not push or include `.zcode/`, `reports/CODEBASE_ANALYSIS.md`, or unrelated files.

VoXtream export shortcomings discovered during review—only layer 0 being emitted, stale root identity after mutation, and missing `audio_embeddings`—will be addressed as an explicit prerequisite artifact-export commit before Orion requires all four seqpack artifacts. Both repositories are authorized, but commits remain repository-local and logically separated.

## 1. Centralize BLOBFILE chunk parsing and validation (ORION-0031 foundation)

Add a small shared C helper under the existing compiler/core boundary that validates one BLOBFILE chunk from either mapped bytes or file-backed data using the same contract:

- checked offset/range arithmetic;
- 64-byte chunk header framing and magic/version validation;
- declared payload size and payload offset validation;
- payload range extraction;
- optional expected SHA-256 validation;
- stable structured failure reasons suitable for callers to translate into their current diagnostics.

Refactor the duplicate implementations in:

- `compiler/binding_plan.c`;
- `core/ane_runtime.m`;
- `apps/cli/commands/depth_canonical.m`.

Preserve each caller’s existing public behavior and error boundary. Reconcile aggregate framing correctly: the physical aggregate has a 128-byte file header, while plan weight entries point to per-chunk BLOBFILE headers and generic single-chunk artifacts may start at offset 64. Do not retain the current blanket assumption that every valid chunk offset must be at least 128.

Add portable unit coverage for valid chunks and malformed magic/version, overflow, truncated headers/payloads, mismatched declared lengths, invalid payload offsets, and hash mismatch. No ANE or model blobs are required.

Commit: `feat(blobfile): centralize chunk payload validation`

## 2. Make VoXtream publish a complete canonical seqpack artifact set

In `/Users/dekal/tooling/voxtream`, extend the packed export flow to produce deterministic seqpack artifacts for all four depth layers rather than only `layer0`:

- recompute/finalize root identity only after all manifest mutations;
- include or correctly reference the required audio embeddings artifact so the resulting export is self-contained for depth-serve startup;

Add Python tests for all-layer inventory, deterministic identity, sidecar/blob consistency, and incomplete-input rejection. Avoid generating or committing model artifacts.

## 3. Extend shared canonical depth helpers to seqpack

Update `apps/cli/commands/depth_canonical.h/.m` so separate-CFG and seqpack share one artifact/plan construction path rather than keeping seqpack manifest parsing in `depth_serve.m`.

Introduce a seqpack compile-unit builder that:

- loads the root manifest’s complete seqpack inventory;
- resolves blob and sidecar paths within the export root after symlink resolution;
- validates schema, layer coverage, aggregate digest, chunk inventory, chunk framing/ranges, and `chunk_sha256` through the shared BLOBFILE helper;
- constructs `orion_frontend_voxtream_depth_probe_seq_pack_adapter(layer, 0, NULL)`;
- validates and optimizes the graph;
- rewrites each BLOBFILE reference to the sidecar-declared aggregate path and absolute chunk offset;
- code-generates MIL;
- generates a binding plan with identity, binds the MIL identity, finalizes it, verifies the expected one-input/one-output ABI, and validates the weight dictionary.

Factor common graph rewrite and finalized-plan construction where practical, while retaining stable mode-specific failure tokens. Keep final norm host-side in seqpack mode.

Commit: `feat(depth): add canonical plan-aware seqpack units`

## 4. Migrate depth-serve seqpack compile, surfaces, and evaluation to plans

Remove the raw seqpack-only helpers from `apps/cli/commands/depth_serve.m` (`seqpack_offsets`, raw ref rewriting/MIL generation, and `compile_seqpack_layer`).

For each of the four seqpack layers:

- build the canonical seqpack unit through `depth_canonical`;
- store its finalized `OrionBindingPlan` in `DepthWorker.layer_plans`;
- compile with `orion_compile_mil_with_plan` while preserving the exact four-compile ledger and fail-closed cleanup;
- derive program identities from finalized plan/artifact provenance rather than an unverified whole-blob shortcut, without changing the existing receipt schema;
- allocate persistent chain surfaces with `orion_tensor_create_for_binding` according to the plan ABI;
- evaluate with `orion_eval_with_plan_report`, retaining invocation counters and phase-timing accumulation;
- preserve packed `[1,1024,1,64]` CFG layout, 60 evaluations per frame, checked host RMSNorm, token recurrence, and current failure semantics.

Separate-CFG behavior and its final-norm plan remain unchanged. Startup must fail before readiness if any of the four seqpack artifacts, plans, or ABI bindings are invalid.

Commit: `feat(depth-serve): use plans for seqpack execution`
